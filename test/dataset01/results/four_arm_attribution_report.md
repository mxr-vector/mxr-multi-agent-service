# 四臂归因终版（2026-08-29）

## 背景

四臂对照（LongBench 多跳三子集 ×200，600 条）分离"对话模型升级"与"分层工具"的净贡献。
glm 对照臂结果：68.3%（410/600，0 timeout / 0 failed）。

## 四臂结果

| 臂 | 模型 | 分层工具 | ok | 准确率 | 平均延迟 |
|---|---|---|---|---|---|
| 历史锚点 | mimo-v2.5 | ✗ | 600 | 34.5% | 38s |
| **glm 对照臂** | glm-5.3-flash | ✗ | **600** | **68.3%** | **78s** |
| glm 工具臂（修复前） | glm-5.3-flash | ✓（chunk_read 缺陷） | 598 | 66.9% | 124s |
| glm 工具臂（修复后） | glm-5.3-flash | ✓ | 574 | 65.7% | 92s |

分子集（glm 对照 vs 工具臂）：2wikimqa 0.670→0.617（−5.3pt）｜hotpotqa 0.735→0.750（+1.5pt）｜musique 0.645→0.606（−3.9pt）

## 统计判定

工具净贡献 Δ = 65.7% − 68.3% = −2.6pt，两比例 z 检验 z = −0.97（|z| < 1.96），**差异不显著**。
分子集方向不一致，属混合噪声。

## 结论（修正此前归因）

1. **34.5% → 68.3% 的全部提升来自对话模型升级（mimo → glm-5.3-flash）**，+33.8pt。
   此前报告"34.5%→66.9% 组合路线成立"缺少同模型对照，归因错误，本报告修正。
2. **分层工具（entity_relation_lookup / chunk_read）净贡献 ≈ 0（不显著的轻微负向）**。
   使用率 16% 的题经由工具答对 57 题，但额外轮次与上下文稀释了整体表现。
3. chunk_read 的 UUID 格式修复是正确性/安全性修复（行为契约），不改变净效果——
   修复前 chunk_read 几乎不被调用（4 次），修复后依然很少（3 次）：模型拿到
   关系查询的事实句后极少需要读来源块全文。
4. 成本：工具臂延迟比对照高 18%~60%（多轮工具循环）。

## 架构启示（对"证据交给推理层"的再修正）

- "证据交给推理层消费"的机制成立（工具确实被消费并产出正确答案），
  但在**模型本身已经足够强**时，混合检索 + wiki 导航已提供足够证据，
  额外的确定性工具层没有边际价值——推理层自己会通过多轮 search 完成 bridging。
- 工具层的真实价值场景可能是**弱模型/小上下文**（多轮 search 成本高或能力不足时，
  廉价的确定性事实句查询替代昂贵推理轮次）。当前强模型 + 1M 上下文下不成立。
- 上一代"工具级塞终排"贡献 0/781 的教训依然成立：检索层不应替推理层做消费决策。

## 遗留决策

- 生产 `AGENTIC_TOOLS_ENABLED` 默认值：待定（保留开启 / 默认关闭 / 按查询路由）。
  净贡献≈0 + 延迟 +60% vs 保险价值（未来弱模型场景）。
- 关系索引（32,953 条）与构建器保留：数据资产无维护成本，重新启用只需开开关。

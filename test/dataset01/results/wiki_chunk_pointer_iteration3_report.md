- `TopicPage.chunks` 块级指针（页仅存 id 不落正文，符合"wiki 仅摘要"定位）；
- `wiki/pointers.py` 离线锚定（含页面实体的首个叶块，回退首块），幂等；
- 存量 2,194 页全量挂接（43,613 指针，零重新生成），抽检全部解析为真实块；

## 结论

1. **"按 id 查块"本身不是瓶颈**：块级指针结构正确、确定性消除了在线猜块，
   但所有指标持平——wiki 候选和共现候选一样，卡在同一处：统一重排 + 2 席
   容量的**终选层**。这与迭代二（逐实体轮转失败）互为印证：约束在"挑不准/
   挑不满"，不在"供不上、找不到块"。
2. 两次结构实验（块指针、逐实体重排）均指向同一结论：当前 rerank 模型对
   "桥接证据 vs 原问题"的判别力是天花板。剩余可动的杠杆：
   - quota 扫描（2→3，纯参数，半小时验证）；
   - 方案③离线边事实摘要（直接增强 rerank 输入的判别信号）。
3. 仪器仪表缺口：wiki 候选未带 expansion_source 溯源落盘，本轮无法区分
   "wiki 块进终排被淘汰"与"压根没进池"，下轮实验前应补上。

## 建议

块级指针基础设施保留（结构正确、零维护、wiki 通道语义更干净）；若 quota
扫描仍无增益，则本语料上的多跳优化到此收敛，下一步收益依赖方案③或换
结构化语料验证。
